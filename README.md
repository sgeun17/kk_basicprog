# 학원 운영 관리 프로그램

건국대학교 전공기초프로젝트 2026-2 / A07팀

학원의 학생·강사·과목·반·수강 등록을 관리하는 명령줄 프로그램이다.
모든 데이터는 사람이 열어 읽고 고칠 수 있는 탭 구분 텍스트 파일에 저장한다.

---

## 실행

Python 3.10 이상이 필요하다. 외부 라이브러리는 쓰지 않는다. (2.1)

```
python main.py        윈도우
python3 main.py       맥
```

### 처음 실행하면

`data` 폴더가 없으면 프로그램이 직접 만든다. (2.3.1)

1. `data` 폴더 생성
2. 데이터 파일과 필요한 헤더 생성 (`datetime.txt`는 헤더가 없다)
3. 원장 계정의 사용자 ID와 비밀번호 입력
4. 최초 가상 현재 일시 입력
5. 무결성 검사
6. 로그인 화면

이 프로그램은 실제 시계를 쓰지 않는다. `data/datetime.txt`의 마지막 줄이
"지금"이고, 원장이 메뉴에서 바꿀 수 있다.

처음부터 다시 하려면 `data` 폴더를 지우고 실행하면 된다.

## 구조

```
main.py           시작·종료, 최초 실행, 로그인, 역할별 메뉴          1
ui.py             공통 입력: 메뉴 번호, Y/N 확인, 필수 값, /cancel   1
data.py           파일 읽기·쓰기, 값 검사, 무결성 검사, 공통 계산      2
admin.py          원장: 학생·강사·과목·반 관리                     3 (학생 관리 5)
enrollment.py     수강 신청·취소, 학생·강사 메뉴, 원장 수강 등록 조회  4
virtual_time.py   가상 현재 일시 조회·변경                         5
errors.py         오류 코드와 메시지                               5

data/             실행하면 생긴다. git 에 올리지 않는다
docs/             기획서, 검사 결과. 제출 압축에는 넣지 않는다
```

오른쪽 숫자는 WBS 담당 번호다.

### 파일끼리의 연결

**`import`는 위에서 아래로만 한다.**

```
main.py
   ↓
admin.py   enrollment.py   virtual_time.py     ← 셋은 서로 import 하지 않는다
   ↓
ui.py      data.py
   ↓
errors.py
```

- `main.py`는 아무도 import 하지 않는다
- `admin.py`와 `enrollment.py`는 서로 import 하지 않는다.
  반 관리는 정원을 바꿀 때 수강 인원이 필요하고, 수강 신청은 반 정원이 필요하다.
  둘이 서로를 불러오면 누가 누구에게 기대는지 꼬여서 설명하기 어려워지고,
  `from admin import ...`처럼 쓰는 순간 실제로 켜지지 않는다.
  그래서 **둘 다 필요한 계산은 `data.py`에 둔다** (`count_enrolled`, `is_schedule_conflict` 등)

다른 파일의 함수는 파일 이름을 붙여서 부른다. 어느 파일에 있는 함수인지 바로 보인다.

```python
import data
import ui
import errors

users = data.read_users()
if ui.ask_yes_no("반 C0001(수학 A반)을 폐강"):
    ...
print(f"[{errors.E_AUTH_FAIL}] {errors.ERROR_MESSAGES[errors.E_AUTH_FAIL]}")
```

### 메뉴에 기능을 연결하는 방법

메뉴는 `main.py`(1)가 만든다. 각자 기능 함수를 만들고 **이름을 노션에 적으면**
1이 메뉴에 연결한다.

기능 함수는 **로그인한 사용자 레코드를 인자로 받는다.**

```python
def enroll_class(user):
    student_id = ...   # user["사용자ID"] 로 students.txt 에서 찾는다
```

아직 연결 안 된 메뉴는 "준비 중"이 뜬다. 최종 통합 전에 전부 지운다.

## 사양

사양은 `docs/` 안의 기획서 **하나뿐이다.**

구현 중에 "이게 맞나" 싶으면 기획서의 절 번호를 찾아본다.
사양을 다른 문서에 옮겨 적지 않는다. 두 개가 되면 한쪽이 낡는다.

| 찾는 것 | 절 |
|---|---|
| 값의 형식 규칙 (ID, 이름, 날짜, 정원…) | 4장 |
| 파일 공통 규칙 (인코딩, 탭, 빈 값…) | 5.1 |
| 파일별 헤더와 예시 | 5.2 |
| 무결성 검사 8단계 | 5.4 |
| 메뉴 화면, 입력 규칙, 오류 메시지 | 6장 |
| 기능 테스트 기준 | 7.1.1 |

## 이름 규칙

함수와 변수는 영어 `snake_case`, 안 바뀌는 값은 대문자 `UPPER_CASE`다.
따옴표 안(딕셔너리 키, 화면 메시지)과 주석은 한글이다.

기획서 용어는 이 표대로 옮긴다. 한 용어에 두 단어를 쓰면 나중에 섞인다.

| 기획서 | 코드 | 기획서 | 코드 |
|---|---|---|---|
| 학생 | `student` | 정원 | `capacity` |
| 강사 | `teacher` | 교시 | `period` |
| 원장 | `admin` | 요일 목록 | `weekdays` |
| 과목 | `subject` | 상태 | `status` |
| 반 | `class_` | 연락처 | `phone` |
| 수강 등록 | `enrollment` | 일시 | `dt` |
| 사용자 | `user` | | |

- "수강 등록"은 `enrollment` 하나로 쓴다. `registration`은 쓰지 않는다
- `반`은 `class_`다. `class`가 파이썬 예약어라 뒤에 밑줄을 붙인다. 복수는 `classes`
- 이름이 `_`로 시작하는 함수(`data._read_table` 등)는 그 파일 안에서만 쓴다.
  다른 파일에서는 `data.read_users()`처럼 밑줄 없는 함수를 쓴다

## 팀 합의

1. **레코드는 딕셔너리.** 키는 파일 헤더 글자 그대로. `rec["이름"]` ○ / `rec[1]` ✗
2. **읽다가 파일이 깨졌으면 예외, 쓰다가 실패하면 False.**
   `data.read_*`는 형식이 틀리면 `errors.DataError`를 던진다. 받는 쪽은 `e.code`, `e.message`를 출력한다.
   `data.write_*`는 실패하면 `False`를 돌려준다. 받는 쪽은 `[E_SAVE]`를 출력한다
3. **오류 코드와 메시지는 `errors.py`에서 가져다 쓴다.** 직접 치지 않는다.
   7.1.1 기능 테스트가 화면에 나온 문장을 보고 판정하므로 문장을 고쳐 쓰면 안 된다
4. **가상 현재 일시는 쓸 때마다 `data.now()`로 읽는다.** 변수에 담아두지 않는다.
   담아두면 6.3에서 바꿨을 때 옛날 값으로 판정하게 된다
5. **파일을 직접 `open(path, "w")`로 덮어쓰지 않는다.** `data.write_*`를 쓴다.
   `open(..., "w")`는 여는 순간 파일을 비워서, 쓰다 죽으면 데이터가 날아간다
6. **화면 출력은 각자.** 2.1 — "정확한 공백 수 자체를 출력 규칙으로 보지 않는다"

## 작업 규칙

- 자기 파일만 고친다. 다른 사람 파일을 고쳐야 하면 먼저 말한다
- 올리기 전에 `git pull`. 브랜치·병합 규칙은 WBS 상 5가 정한다
- 고친 버그는 노션에 한 줄씩 남긴다. 발표 때 "기획서와 다르게 동작한 원인이
  어디 있었고 어떻게 고쳤는지"를 설명해야 한다

```
증상: 정원 10인 반에 11번째 수강 신청이 됨
원인: enrollment.py 의 enroll_class — "취소" 등록까지 세고 있었음
수정: data.count_enrolled 로 "수강중"만 세게 바꿈
```

- 외부 라이브러리를 쓰지 않는다. `pip install`이 필요한 코드는 못 쓴다
